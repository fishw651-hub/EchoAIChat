# 私聊表情包与单轮表情回复设计

> 状态：已确认设计（仅设计文档，暂不进入实施）  
> 日期：2026-07-19  
> 适用版本：回响 Flutter 客户端 + Go API 服务器

## 1. 目标与非目标

### 目标

本设计为私聊智能体增加一个微信式底部表情面板。用户可以从本机全局共享的表情库中选择表情发送；添加表情时手动选择图片并填写描述。智能体可以在一次 `chat` 工具调用中同时返回文字和最多一个表情包，不再为聊天和表情工具分别发起请求。

后台增加视觉识图测试能力：管理员可以配置视觉 API、模型和输入/输出 Token 价格，上传图片进行测试并查看 usage 与估算成本。该能力只用于内部测试，不接入普通用户流程。

### 非目标

- 只支持私聊，群聊不增加表情面板、表情工具或表情上下文。
- 表情图片和表情库不纳入多端同步；不上传到业务服务器。
- Flutter 客户端不出现“AI 识图添加表情”入口，也不会在用户添加表情时自动调用视觉 API。
- 视觉识图暂不上架、不开放普通用户接口、不参与普通聊天配额扣减。
- 不修改三份协议和其他法律文本。

## 2. 现有系统衔接

### Flutter

- 私聊入口位于 `lib/screens/chat_screen.dart`，状态和消息发送由 `lib/providers/chat_provider.dart` 管理。
- `ChatMessage` 已支持 `imagePath`，但表情需要区分“普通图片消息”和“带语义描述的表情消息”。本设计不把表情图片路径写入同步的 `chat_messages` 行，而是使用本地辅助表保存渲染信息。
- SQLite 当前版本为 26，升级到 27 时创建本地表。现有 `SyncService.syncTables` 不增加表情相关表。
- `ApiService.chatCompletion` 已支持 `tools` 和 `tool_choice`；私聊工具定义中已有 `chat` 和 `plan`，需要把 `chat` 扩展为复合回复工具。

### Go API 与后台

- `/api/v1/chat/completions` 已负责模型权限、配额预留、DeepSeek 中继和结算。表情回复沿用同一聊天请求，不增加普通用户端点。
- 后台模型价格当前使用 `ModelPrice`。视觉模型价格单独建表，避免视觉模型被普通聊天模型列表和聊天权限判断误识别。
- 系统配置使用 `SystemConfig`，API Key 使用现有加密的 `APIKey` 记录。视觉配置通过独立的管理员路由暴露。

## 3. 用户体验

### 底部表情面板

输入栏新增表情按钮。点击后，面板从底部升起，覆盖输入区上方，保持以下三个状态：

1. **选择表情**：显示“我的表情”网格、每个图片下方显示实际描述文本，以及“添加”和“管理”入口。
2. **添加表情**：用户选择本地图片，手动填写描述后保存。描述去除首尾空格后不能为空，长度最多 30 个字符。
3. **管理模式**：点击某个表情进入编辑描述流程；删除操作必须二次确认。普通模式点击表情立即发送。

表情库不按智能体分组，所有私聊智能体看到同一份本机列表。表情图片保存在 App 私有目录，数据库存储可恢复的本地路径。

### 用户发送语义

点击表情会像发送普通文字一样触发一次智能体回复。表情本身不作为图片上传给聊天 API，只使用它的描述语义。

描述字段不是固定字符串“形容词”，而是用户填写的实际内容：

| 用户填写的描述 | AI 上下文中的内容 |
| --- | --- |
| `开心` | `[表情]开心` |
| `委屈巴巴` | `[表情]委屈巴巴` |

如果用户同时输入文字和表情，短期记忆与聊天上下文追加一行表情标记，例如：

```text
今天真不错
[表情]开心
```

如果用户只发送表情，消息内容就是 `[表情]开心`。这段规范化文本是 AI 的真实输入；本地图片只用于聊天记录的视觉展示。

### 智能体发送语义

智能体每轮最多发送一个表情包。若同时有文字和表情，聊天界面先展示文字，再在同一条助手消息中展示表情图片；若文字为空，则只展示表情图片。

如果历史消息对应的表情已被删除或图片文件不可读，界面使用 `[表情]描述` 文本占位，不抛出异常。编辑表情描述只影响后续消息，历史消息保留发送当时的描述快照。

## 4. 本地数据模型

### `stickers`

该表是本机全局表情目录，不含 `agent_id`，不纳入同步：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `TEXT PRIMARY KEY` | UUID，供工具调用选择 |
| `description` | `TEXT NOT NULL` | 用户填写的实际描述 |
| `image_path` | `TEXT NOT NULL` | App 私有目录中的图片路径 |
| `created_at` | `INTEGER NOT NULL` | 创建时间戳 |
| `updated_at` | `INTEGER NOT NULL` | 最近编辑时间戳 |
| `deleted_at` | `INTEGER NULL` | 软删除时间；普通列表只查询为空的记录 |

图片写入 `sticker_assets/` 私有目录。添加流程先复制图片并确认文件可读，再写入数据库；任一步失败都不创建可见表情。

### `local_sticker_messages`

该表保存聊天记录的本地视觉渲染信息，不修改同步的 `chat_messages` 结构：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `chat_message_id` | `INTEGER PRIMARY KEY` | 对应本机 `chat_messages.id` |
| `sticker_id` | `TEXT NULL` | 发送时使用的表情 ID；表情删除后可失效 |
| `description_snapshot` | `TEXT NOT NULL` | 发送瞬间的描述，例如 `开心` |
| `image_path_snapshot` | `TEXT NOT NULL` | 发送瞬间的本地图片路径 |
| `created_at` | `INTEGER NOT NULL` | 创建时间戳 |

聊天消息本身的 `content` 仍保存规范化文本 `[表情]描述` 或“文字 + 换行 + `[表情]描述`”。渲染层在本地辅助表存在且图片可读时隐藏该标记并展示图片；在其他设备同步后，由于本地辅助表和图片不存在，只显示规范化文本，这符合“表情包不纳入多端同步”的约束。

删除表情时只隐藏目录记录。若仍有 `local_sticker_messages` 引用其图片，则保留图片快照；没有引用时才删除文件。删除聊天消息时一并删除对应的本地辅助记录。

### 数据库迁移

SQLite 从版本 26 升到 27：

1. 创建 `stickers` 和 `local_sticker_messages`；
2. 不删除、不重命名任何旧列；
3. 不把新表加入 `SyncService.syncTables`；
4. 对旧聊天记录不做回填，旧记录继续按现有文字/图片逻辑显示。

## 5. 单次 AI 工具协议

### 动态表情清单

每次私聊请求构造工具定义时，读取未删除的全局表情目录，向模型提供 `id`、当前描述和“只能从清单选择”的约束。系统提示词同时说明：

- `[表情]描述` 是对话中的语义标记；
- `描述` 是用户为图片填写的实际文字，不是固定字段名；
- 只能选择当前清单中的 `sticker_id`；
- 每次最多选择一个表情；
- 需要回复时使用 `chat` 工具。

图片二进制不放入聊天上下文，也不发送给聊天模型。

### 复合 `chat` 工具

私聊 `chat` 工具扩展为以下逻辑结构：

```json
{
  "name": "chat",
  "parameters": {
    "type": "object",
    "properties": {
      "message": {
        "type": "string",
        "description": "给用户的自然语言文字；只发表情时可以为空"
      },
      "sticker_id": {
        "type": "string",
        "description": "可选，只能使用本轮清单中的表情 ID"
      }
    },
    "required": []
  }
}
```

参数对象至少应包含 `message` 或 `sticker_id`。客户端对空对象、无效 ID、多个表情字段或不存在的表情进行本地校验。

### 单请求处理顺序

1. 客户端构造系统提示词、短期消息和动态工具清单。
2. 客户端发送一次聊天请求；不发送图片、不追加 `tool` 结果消息。
3. 客户端解析响应中的 `chat` 工具参数；同一响应中的 `plan` 工具最多执行一次，但不触发下一轮模型请求。
4. `sticker_id` 有效时读取当前表情图片和当前描述，生成助手消息规范化内容：文字后追加 `[表情]描述`；描述为空时不生成表情标记。
5. 保存消息和本地视觉快照，更新聊天界面和短期记忆。

请求使用 `tool_choice=auto` 以兼容当前服务端对参数的降级逻辑；系统提示词要求最终聊天使用 `chat`。如果模型直接返回普通 `content` 而未调用工具，客户端照常展示文字，但不生成表情。客户端绝不因缺少工具调用再次请求模型。

### 失败降级

- `sticker_id` 不存在、已删除或图片不可读：忽略表情，继续展示 `message`；若 `message` 为空，则显示“表情暂时不可用”本地错误提示，不写入空助手消息。
- 工具参数 JSON 无法解析：尝试使用响应中的普通文字；没有文字时结束本轮并保留错误状态。
- AI 请求失败：用户表情消息已经本地保存，保留重试入口，重试不得重复插入用户消息。
- 模型返回多个 `chat` 调用：只采用第一个合法调用，并记录调试日志，不执行循环。

## 6. 后台视觉识图测试

### 配置

视觉能力独立于聊天模型配置，包含：

- 供应商名称；
- OpenAI 兼容的视觉 `base_url`；
- 视觉模型名；
- 启用状态，默认关闭；
- 加密 API Key，使用现有 `APIKey` 存储机制并以 `provider=vision` 区分。

`base_url`、模型名和启用状态保存为 `SystemConfig`；API Key 不写入普通配置值、不回显明文、不记录日志。

### 价格

视觉模型使用独立的 `VisionModelPrice` 数据记录，至少包含模型 ID、每百万输入 Token、每百万输出 Token、状态和时间戳。视觉价格不复用 `ModelPrice`，不参与 `/api/v1/models` 普通聊天列表。

本次测试成本计算公式为：

```text
输入成本 = prompt_tokens / 1,000,000 × input_price_per_1m
输出成本 = completion_tokens / 1,000,000 × output_price_per_1m
总成本 = 输入成本 + 输出成本
```

图片产生的视觉 Token 计入输入 Token。供应商未返回 usage 时，测试结果显示“无法计算成本”，不根据图片大小或文字长度猜测费用。

### 管理员接口与页面

后台增加独立的“视觉识图测试”区域：

- `GET /api/v1/admin/vision/config`：读取掩码后的配置；
- `PUT /api/v1/admin/vision/config`：保存供应商、URL、模型、启用状态和可选 API Key；
- `GET /api/v1/admin/vision/prices`：读取视觉价格；
- `PUT /api/v1/admin/vision/prices/:id`：更新输入/输出 Token 价格和状态；
- `POST /api/v1/admin/vision/test`：管理员上传图片并提交测试提示词，返回识别结果、usage 和可计算时的成本。

所有接口必须经过现有 JWT 和管理员角色中间件。`POST /vision/test` 仅用于管理后台，不能被普通 App 用户调用；Flutter 添加表情流程不调用该接口。

### 图片限制与上游请求

- 只接受 `image/jpeg`、`image/png`、`image/webp`，并通过文件内容检测而非扩展名单独判断；
- 单张图片最大 10 MiB，上游视觉请求超时 30 秒；
- 测试图片只在请求生命周期内使用，不写入业务数据库和用户文件目录；
- 上游错误只向管理员返回通用错误信息，详细错误写服务器受控日志，不包含 API Key。

## 7. 错误处理与安全

### Flutter

- 图片选择、复制、数据库写入均使用可恢复错误提示；面板不会因单张损坏图片崩溃。
- 删除和编辑操作只影响本机表情目录；历史消息依赖快照，不因目录变更丢失语义。
- 所有涉及消息的查询仍按现有 `agent_id` 过滤；全局表情目录是明确的非消息资源，不使用伪造的智能体 ID。
- 表情描述作为模型输入时必须按普通文本处理，不执行任何 Markdown、HTML 或工具片段。

### Go API 与后台

- 视觉配置和测试接口只允许管理员访问；普通用户端路由表不增加视觉端点。
- API Key 使用现有加密服务保存，响应只返回掩码；日志禁止记录请求头和完整配置。
- 视觉测试不创建聊天计费预留，不改变用户余额、订阅、免费配额或真实回复配额。
- 价格字段拒绝负数和非有限数字；未启用模型不能执行测试。

## 8. 测试与验收标准

### Flutter 自动化测试

- 添加、编辑、删除表情后，所有私聊智能体都能读取同一全局目录。
- 图片路径无法读取时，列表和聊天历史显示占位文本而不抛异常。
- 用户只发表情时，短期记忆和 API 消息严格包含 `[表情]实际描述`。
- 用户文字加表情时，文本和标记按换行组合，描述不是字面量“形容词”。
- AI 返回文字和合法 `sticker_id` 时，一次响应生成一条文字+图片助手消息。
- AI 返回无效 ID、空对象、多个调用或普通文字时，按降级规则处理且不发送第二次请求。
- 新数据库从 26 升级到 27 后，旧聊天、旧图片和旧智能体数据可读取。
- `stickers` 与 `local_sticker_messages` 不出现在同步 payload 中。

### Go 自动化测试

- 非管理员访问视觉配置和测试接口返回未授权/无权限。
- 配置更新正确加密 API Key，列表接口不返回明文。
- 视觉价格按输入/输出 Token 正确计算；usage 缺失时成本为空而不是 0 或猜测值。
- 非法 MIME、超大图片、未启用配置、上游超时和上游非 2xx 响应均返回明确错误。
- 视觉模型不会出现在普通聊天模型列表，也不会参与普通聊天配额逻辑。

### 手工验收

1. 打开私聊，点击表情按钮，确认面板从底部出现并可切换添加/管理状态。
2. 添加一张图片并填写“开心”，切换不同智能体，确认都能看到它。
3. 点击该表情，确认用户消息展示图片，AI 上下文和短期记忆为 `[表情]开心`。
4. 确认智能体能在一次回复中同时发送文字和最多一个表情，网络日志中没有第二次补充请求。
5. 删除表情后发送历史消息，确认历史仍显示图片或 `[表情]开心` 占位，新表情清单不再提供该 ID。
6. 在管理后台配置视觉模型、价格并上传图片测试，确认显示识别结果和 usage/成本；普通 App 用户无法调用该能力。

## 9. 后续明确不做

以下内容不属于本设计的实施范围：

- 群聊表情、导演 AI 或群聊工具集改造；
- 表情图片云端上传、服务器存储和多端同步；
- Flutter 端自动识图、AI 生成描述或识图入口；
- 普通用户视觉 API、视觉模型上架、视觉调用配额和正式计费；
- 表情搜索、分类、排序、动图处理和批量导入；
- 与三份协议、网络市场或订阅权益相关的扩展。
