# Flutter 与 Go 后端安全性能加固设计

日期：2026-07-11

## 目标

在保持现有 Flutter 数据和公开 API 兼容的前提下，将 Go 后端从 JSON 文件数据库迁移到 SQLite，修复已确认的计费绕过、管理员越权、客户端凭据泄露、群聊记忆串写与资源耗尽问题，并降低网络连接、数据库落盘和 Flutter 启动/构建阶段的性能开销。

## 范围

### Go 后端

- 聊天请求在访问 DeepSeek 前执行额度预检和费用预占，响应后按真实用量结算。
- 同一用户的额度检查、预占、结算和退款串行化，防止并发超额消费。
- 普通管理员不能创建、提升、修改或删除超级管理员，也不能修改管理员余额和角色。
- HTTP 服务配置请求头、请求体、读、写和空闲超时。
- JSON 与 Multipart 请求使用明确的大小上限；Base64 图片在解码前检查估算大小。
- IP 限流器增加最后访问时间和定期淘汰，避免 Map 无限增长。
- 显式配置可信代理；默认不信任任意 `X-Forwarded-For`。
- DeepSeek、支付和爱发电请求复用带连接池的 HTTP Client。
- 使用 SQLite 替换 JSON 文件数据库，启用 WAL、外键、忙等待超时和事务。
- 保留现有 `DB/Table/Filter` 业务调用接口作为迁移适配层，避免同时重写全部 Handler。
- 首次启动自动导入 `data/*.json`，完成记录数校验后将旧文件移动到带时间戳的只读备份目录。
- 修复 `go vet` 报告的不可达代码。

### Flutter 客户端

- JWT、刷新令牌和 API Key 迁移到系统安全存储。
- 不再持久化登录密码；旧 SharedPreferences 凭据在启动时删除。
- 保留非敏感用户资料和订阅缓存于 SharedPreferences。
- 群聊每个并行角色使用独立 `MemoryService`，不共享可变 agent/group 上下文。
- 后台 Memory AI 使用独立上下文，避免与私聊切换或下一轮群聊竞争。
- `MemoryService` 的数据库写入改为可等待操作，关键消息顺序由调用方等待完成。
- 新建 SQLite 数据库时直接创建全部查询索引，旧数据库打开时幂等补齐索引。
- 启动清理不再执行阻塞式 `VACUUM`，改用 WAL checkpoint 和按需维护。
- API 请求复用 `http.Client`，由服务生命周期统一释放。
- 聊天背景文件存在性在状态变化时计算，不在 Widget build 中同步访问磁盘。

## 计费状态机

1. 校验模型和账户状态。
2. 根据请求的 `max_tokens`、模型价格和思考模式计算保守的最大预留金额。
3. 在用户级锁内重新读取额度并原子增加“已用额度”，生成预留对象。
4. 调用 DeepSeek。
5. 成功后依据真实 token 计算费用，在同一用户级锁内退回差额并写 UsageRecord。
6. 上游失败、客户端取消或响应解析失败时释放全部预留。
7. 若预留失败，请求不得访问 DeepSeek。

预留记录持久化到 SQLite `billing_reservations` 表。创建预留、增加已用额度、结算、退款和写入 UsageRecord 均在事务内完成；启动时释放超过上游最长超时时间仍处于 pending 的陈旧预留。

## 权限模型

- `super_admin`：可管理角色、状态、余额、管理员账户和系统配置。
- `admin`：可处理内容审核、普通用户支持和业务数据，但不能授予或修改管理员权限。
- `user`：仅访问用户 API。
- JWT 中的角色只作为身份提示；管理接口每次请求从数据库重新读取当前角色和状态。

## 数据兼容与迁移

- Flutter 首次启动读取旧 XOR 数据，仅用于迁移 JWT/API Key 到安全存储；迁移成功后删除旧敏感键和所有保存的用户名/密码。
- 无法解密的旧值直接清除并要求重新登录，不记录原始内容。
- SQLite 主文件为 `data/aichat.db`。迁移器在数据库事务中逐表导入旧 JSON，并记录 `schema_migrations` 标记。
- 只有全部表导入成功、记录数一致且 SQLite 文件同步完成后，才把旧 JSON 移入 `data/legacy-json-<timestamp>/`。
- 若迁移失败，事务回滚并继续保留原 JSON；服务拒绝启动，避免两个存储同时接受写入。
- 迁移完成后 JSON 不再作为运行时回退数据源；回滚必须停止服务、恢复备份并使用旧版本程序。
- SQLite 适配层为常用的 `ID`、`UserID`、`ClientID`、`OrderNo`、`Status`、`UpdatedAt` 建立索引；任意旧式闭包 Filter 在适配层内作为兼容路径执行，后续热点逐步替换为结构化查询。
- Flutter 客户端 SQLite 仅增加索引，不更改表或业务字段，不提高客户端 schema version。

## 错误处理

- 客户端只显示通用网络或认证错误，敏感响应体不写日志。
- 后端上游错误限制返回长度，不回传完整供应商响应。
- SQLite 事务失败必须整体回滚并返回错误；禁止静默吞掉关键计费写入错误。
- 预留释放失败记录高优先级日志，后续请求重新读取持久化额度。

## 测试策略

### Go 回归测试

- 余额不足时 DeepSeek 调用次数为零。
- 两个并发请求不能同时通过同一份不足额度。
- 上游失败释放全部预留；真实费用低于预留时退回差额。
- 普通管理员不能提升角色或修改超级管理员。
- 超限 JSON、Multipart 和 Base64 图片返回 413/400。
- 限流器淘汰过期 IP；伪造转发头在未信任代理时无效。
- JSON 导入失败会回滚 SQLite，原始 JSON 保持不变。
- 完整迁移后所有表记录数与源 JSON 一致，二次启动不会重复导入。
- SQLite 并发写、进程重启和陈旧计费预留恢复测试通过。

### Flutter 回归测试

- 旧敏感偏好迁移后被删除，密码永不写回。
- 各并行群聊角色的 MemoryService 上下文互不影响。
- 新建数据库和旧数据库打开后均存在关键索引。
- API Client 生命周期可复用并正确关闭。

## 验证标准

- `go test ./...` 通过。
- `go vet ./...` 无错误。
- 可用环境下 `go test -race ./...` 通过。
- `flutter analyze` 为 0 errors。
- `flutter test` 通过。
- 不修改法律协议，不重新启用 Kotlin 增量编译，不提交任何真实密钥。

## 非目标

- 本轮不把后端迁移到 PostgreSQL，也不支持多实例共享同一个 SQLite 文件。
- 不改变 DeepSeek 对外请求协议和 Flutter 页面交互设计。
- 不引入 Redis、消息队列或分布式锁；多实例部署前需另行设计共享计费事务。
