# P0/P1/P2 安全与可靠性硬切换设计

## 目标

修复 2026-08-17 静态审计中的 P0、P1、P2 问题，并采用立即硬切换策略：
服务端部署后不再兼容缺少新版安全字段的客户端。更新后的客户端与服务端共同形成新的安全边界。

## 已确认决策

- 本地数据按账号使用独立 SQLite 数据库，不在共享数据库中追加账号过滤列。
- 同步传输由 TLS 保护，服务端使用 AES 加密敏感字段；不实施端到端加密。
- 隐私协议改为准确描述“TLS 传输加密、服务端 AES 加密存储”。
- 旧聊天、退款、同步和主动关心协议立即失效，不保留兼容回退。
- 新客户端版本提升为 v5.3.6（`version_code 67`），高风险接口最低版本设为 67。
- 所有行为修复先添加失败回归测试，再实现最小修复。

## 重新审查结论

### P0 第四项

原审计记录的 `ifdian.go` 编译失败已被并发进行的 Go 架构重构修复。当前
`website/API` 工作树干净，`go test -count=1 ./...` 全部通过。因此不再修改该
编译问题，只新增独立 CI 门禁，保证后续每次变更都执行无缓存 Go 全量测试。

### 普通群聊记忆作用域

原审计结论需要缩小范围。成员回复和记忆 AI 已使用 `agentId + groupId`，不是
空作用域。问题集中在普通群聊的“在场角色”记录：它使用 `groupId` 但
`agentId == null` 写入长期记忆，而读取、更新和删除要求非空 `agentId`。修复应
迁移这一类孤儿记录，并把在场信息写入明确的群共享记忆域。

## 总体架构

修复按五条纵向链路组织：账号数据域、受信任命令与计费、同步与隐私、更新
准入、模型与用量准入。每条链路都由服务端持有权威状态，客户端只发起命令，
不能自行退款、声明归属或决定是否绕过限制。

## 1. 每账号独立本地数据库

### 数据库命名

- 新增账号数据库作用域组件，输入服务端稳定用户 ID，输出不含个人信息的哈希数据库名。
- 原生平台使用 `aichat_u_<sha256-prefix>.db`。
- Web 使用同名的独立 IndexedDB/SQLite 数据库名。
- 未登录状态使用空的 `aichat_guest.db`，不展示任一账号的数据。

### 生命周期

1. 恢复安全会话时，先取得用户 ID，再打开该账号数据库。
2. 登录成功后，在设置 JWT 可用于业务请求之前完成数据库切换。
3. 切换时暂停主动关心、同步和计划任务，关闭旧数据库，打开目标数据库。
4. 数据库切换完成后使 agent、memory、chat、group、profile、sync 等 Provider 失效并重载。
5. 注销时取消后台任务、关闭账号数据库并切到 guest 数据库，不删除账号文件。
6. 后台 isolate 从安全会话读取用户 ID，只允许打开同一用户的数据库；身份或作用域不一致时 fail closed。

### 旧库迁移

- 增加一次性迁移归属记录，旧 `aichat.db` 只能被一个账号认领。
- 首个成功登录且旧库尚未认领的账号获得旧库数据。
- 原生端在 WAL checkpoint 和关闭连接后迁移文件；Web 端逐表事务复制。
- 迁移成功后写入归属和完成标记；中断时可重试，不能让第二个账号认领。
- 新账号始终创建空数据库，随后按同步策略拉取自己的云数据。

## 2. 智能体归属、功能配额与主动关心

### 智能体注册与请求契约

- `UserAgent` 增加全局客户端 UUID `ClientID` 以及真实信息、主动关心相关配置。
- 客户端创建或修改智能体时，登录状态下必须向服务端执行幂等 upsert。
- 聊天请求顶层必须包含 `client_agent_id`、`request_kind` 和 `client_version_code`。
- `request_kind` 仅允许 `chat`、`group_chat`、`proactive_care`。
- 服务端在调用模型或预留配额前验证该智能体属于当前 JWT 用户。
- 缺少字段、智能体不存在或不属于当前用户的请求直接拒绝；不从 prompt 内提取身份。

### 移除公开退款

- 删除用户路由 `/quota/refund` 和 Flutter `QuotaService.refund`。
- OCR 保持“本地识别成功后再消费”，无需退款。
- 真实回复配额不再由 Flutter 预扣。聊天 Handler 根据已登记智能体的
  `RealInfoEnabled` 在服务端内部预留功能配额。
- 上游成功后提交功能配额；调用失败、取消或结算失败时由服务端内部释放。
- 功能配额预留使用不可由客户端释放的一次性记录和原子状态转换。

### 主动关心仲裁

- 新增服务端 `ProactiveCareTask`，唯一业务键为
  `user_id + agent_client_id + local_date + sequence`。
- claim 在事务中检查每日上限、最小间隔、上一条是否已回复、智能体开关和归属。
- claim 返回短期一次性 token；聊天请求的 `request_kind=proactive_care` 必须携带该 token。
- 模型成功且客户端本地消息提交成功后 commit；失败或超时 release。
- claim 与服务端真实回复功能配额预留绑定，跨设备只能有一个有效任务。
- 提交前再次检查账号会话、智能体存在性和配置，删除、注销或关闭开关后不得提交。

## 3. 记忆、画像与同步隐私

### 画像周期与协议

- `MemoryAiScheduler.roundsInterval` 改为 10，更新现有固化为 5 轮的测试。
- 隐私政策明确：同步请求经 TLS 传输，服务端对敏感字段使用 AES 加密存储。
- Cloudflare 应使用 Full (strict) 与源站证书；Flexible 不能宣称源站链路也受 TLS 保护。

### 明确记忆作用域

- 引入不可为空的记忆作用域：私聊智能体、普通群聊成员、群共享三类。
- 长期和基础记忆创建入口拒绝无法解析为上述作用域的请求。
- 普通群聊成员记忆继续使用 `agentId + groupId`。
- “在场角色”改写到 `group_shared_memories`，并迁移或删除既有
  `agent_id IS NULL AND group_id IS NOT NULL` 的孤儿长期/基础记忆。
- 长期记忆最多 15 条的规则下沉到事务写入边界，并定义按更新时间淘汰最旧记录。

### Provider 迟到结果

- LongTermNotifier 和 BaseNotifier 分别维护递增加载世代。
- 每次切换智能体或开始加载时捕获 `agentId + generation`。
- await 返回后仅当两者仍匹配时更新 state；否则丢弃迟到结果。
- 切到空智能体时立即清空 state，并使旧请求失效。

### 服务端 AES 数据分类

- 建立声明式敏感字段注册表，至少覆盖：
  - agents：Persona、OpeningLine、Worldview；
  - user_profiles：Value；
  - long_term_memories：Field、Content；
  - base_memories：Type、Content；
  - short_term_messages：Content；
  - group_shared_memories 和 group_short_term：内容字段；
  - providers：ApiKey。
- 密文使用带版本前缀的 envelope，避免明文、旧密文和新密文混淆或重复加密。
- 启动迁移在事务中把历史明文转换为当前 envelope；读取路径在迁移期兼容旧 AES 密文。
- 同步预览与合并只比较标识、时间戳和版本，不依赖敏感字段明文。

### WebSocket ticket

- 新增认证接口签发 60 秒、一次性、绑定用户和设备的随机 ticket。
- WebSocket URL 只携带 ticket 和 device_id，不再接受 JWT query 参数。
- 服务端在升级连接前原子消费 ticket；重放、过期或设备不匹配均拒绝。
- 日志中统一清除 query 中的 ticket、token、key 等敏感参数。

## 4. 强制更新与包完整性

### 发布模型

- AppVersion 增加 SHA-256、Ed25519 签名和签名算法字段。
- `(platform, version_code)` 建立数据库唯一约束。
- 新建和编辑版本时统一校验平台、版本号、下载源、哈希和签名。
- 外链只允许 HTTPS；使用受限 HTTP client 检查每次重定向和最终地址，拒绝私网、回环、链路本地和非白名单主机。
- 本地文件在服务端计算 SHA-256；外链包在发布前流式读取并校验声明哈希。
- 下载量使用数据库原子 increment，禁止读后写。

### 客户端验证

- 更新检查响应必须完整包含版本、下载路径、SHA-256、签名和算法。
- 客户端下载到临时文件，先校验 SHA-256，再使用内置 Ed25519 公钥验签，成功后才调用系统安装程序。
- 强更下载或校验失败时保留重试、切换网络和重新检查入口，不能进入主应用。
- `_checked` 仅在完整响应通过 schema 验证后置位。
- 持久化最近一次已确认的强更策略；网络失败时仍执行已知且未过期的强更限制。

### 最低版本门禁

- 客户端所有认证业务请求发送版本码与平台头。
- 服务端对聊天、同步、主动关心和功能配额端点强制最低版本。
- 缺少版本头按旧客户端处理并拒绝，返回稳定的 `upgrade_required` 错误和更新信息。
- Web 客户端由部署版本标识参与同一检查，但静态站点更新不走安装包下载。

## 5. 模型准入、用量和旧语义清理

### 单一模型准入

- 新建模型准入服务，以启用的 ModelPrice 记录作为唯一来源。
- 一次解析返回供应商、API 格式、价格、思考支持、视觉支持、工具支持和上游密钥路由。
- 模型列表、聊天校验、计费预留、上游路由和视觉接口都消费同一结果。
- 未配置、禁用或缺少供应商密钥的模型在预留前拒绝。

### 流式 usage

- 对支持 OpenAI 协议的上游发送 `stream_options.include_usage=true`。
- 正常成功优先使用上游 usage。
- 缺失 usage 时调用统一估算器，并在 UsageRecord 中记录
  `usage_source=estimated`、估算器版本和原因；不再使用固定 100/100。
- 流中断按实际已发送内容估算，并同样标记来源。
- 客户端错误只返回稳定错误码；上游响应体仅写入脱敏服务端日志。
- 处理所有 JSON 编解码、请求创建和响应读取错误。

### 删除旧余额语义

- 删除生产代码对 `DeductAndRecord` 的引用并限制或移除该入口。
- 聊天响应删除 `balance_after`。
- API、Flutter 与后台统一使用 quota/usage 字段；数据库历史 `User.Balance` 字段暂保留只读兼容。

## CI 与验证

新增独立 CI 工作流，至少包含：

- `flutter analyze`，不得 `continue-on-error`；
- `flutter test`；
- `go test -count=1 ./...`；
- `go build ./...`；
- 安全迁移、硬切换协议、账号数据库切换和更新包验签的定向测试。

本地验证按风险从定向到全量执行。数据库迁移测试必须覆盖原生与 Web 可测试层；
涉及网络跳转、WebSocket 和强更页面的行为增加 Handler/Service 测试，并使用实际本地
应用进行端到端检查。

## 部署与回滚

这是硬切换发布，不提供旧协议兼容窗口：

1. 备份服务端数据库和更新包。
2. 预先构建、签名并上传 v5.3.6（`version_code 67`）客户端安装包，使公开更新接口可下载，但暂不启用业务门禁。
3. 原子部署包含新 schema、历史加密迁移、新协议和最低版本门禁的服务端，并将高风险接口最低版本设为 67。
4. 服务端立即拒绝缺少新字段、缺少版本头或版本码低于 67 的旧客户端；旧客户端仍可调用公开更新检查和下载接口完成升级。
5. Cloudflare 切到 Full (strict)，确认源站证书和健康检查后更新隐私协议版本。

回滚只能整体回滚服务端和客户端协议版本。AES envelope 和数据库迁移必须向前兼容，
回滚代码不得把密文当明文覆盖。发布前必须保留可验证的数据库备份。

## 非目标

- 不实施客户端端到端加密和用户密钥恢复体系。
- 不恢复永久余额业务。
- 不顺带重写 Go 数据库层或 Flutter 状态管理框架。
- 不处理审计中的 P3 项，除非它是完成上述迁移的必要前置条件。
