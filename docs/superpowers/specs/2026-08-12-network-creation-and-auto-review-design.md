# 网络创建入口、作品归属与自动审核设计

**日期：** 2026-08-12  
**状态：** 已完成交互设计确认，待用户审阅书面规格

## 目标

在 Flutter 客户端的移动端底部导航中加入居中的创建按钮，统一提供“创建智能体”和“创建群聊”入口；把网络上传能力接入智能体和群聊的创建/编辑页面；让发现页点击作品后自动下载、本地落库并进入聊天；建立明确的网络作品归属规则；让服务器在用户上传或作者同步修改后自动执行 AI 审核，并根据结果自动上架或拒绝。

本设计是对现有网络市场功能的增量扩展，继续使用现有 `NetworkAgent`、`NetworkGroup`、上传/下载 API、AI 审核服务和“我上传的作品”页面。

## 已确认业务规则

1. 网络作品的首次上传者是唯一维护者。
2. 原作者修改本地智能体或群聊并保存时，客户端询问是否同步修改网络作品。
3. 选择同步后更新原网络作品，保留网络作品 ID，版本号加一并重新审核。
4. 选择不同步时只保存本地内容，网络作品不变。
5. 下载者只能编辑自己的本地副本，不能修改、下架或更新原网络作品。
6. 下载者的副本即使经过本地修改，也完全禁止通过应用上传为新的网络作品。
7. 智能体和群聊上传时都必须提供非空开场白；缺失时阻止上传并提示“开场白是必须书写的”。
8. AI 审核通过后自动上架；AI 明确拒绝后直接标记为已拒绝，并向上传者展示原因。
9. AI 调用失败、超时或输出无法解析时保持待审核，不能因为系统故障误拒用户作品。
10. 发现页点击智能体或群聊后直接下载、导入本地并进入对应聊天页面。
11. 本地创建成功后同样直接进入对应聊天页面。

## 方案选择

采用“本地来源元数据 + 现有网络作品表 + 服务端身份校验”的方案。

- 客户端模型保存网络作品 ID、上传者 ID、来源角色和网络版本。
- 服务端继续以 `NetworkAgent.UploaderID` / `NetworkGroup.UploaderID` 作为网络作品修改权限的唯一权威来源。
- 下载副本在客户端所有上传入口中被禁止；官方客户端提交来源信息时，服务端再次拒绝下载来源副本。
- 不新建独立作品绑定表，避免增加同步表数量和跨表生命周期管理。

不采用仅隐藏客户端按钮的方案，因为它无法防止伪造更新请求。不采用内容相似度或 AI 查重，因为语义相似不能可靠证明作品来源，而且会引入误判和额外模型成本。

## 客户端导航与创建入口

### 移动端底部导航

现有四个主 Tab 保持不变，布局改为：

```text
首页 | 智能体/群聊 | [+] | 发现 | 账户
```

- 中间按钮是独立命令按钮，不参与 Tab 索引，也不改变当前页面。
- 左右各两个 Tab，中央按钮形成明确视觉分割。
- 点击中央按钮后，在按钮上方显示轻量悬浮单选菜单：
  - 创建智能体
  - 创建群聊
- 菜单使用图标和文字，点击空白处或返回键关闭。
- 智能体多选模式开启时，创建菜单和已有悬浮子页切换控件一样避免覆盖多选操作栏。
- 桌面端保留现有侧边导航，不强行复制底部布局；已有桌面创建入口继续可用。

### 创建后导航

- 创建智能体完成后，将新智能体设为当前智能体并进入 `ChatScreen`。
- 创建群聊完成后，将新群聊设为活动群聊并进入 `GroupChatScreen`。
- 创建失败时留在表单页面并显示具体错误，不发生导航。

## 创建与编辑页面的上传入口

### 智能体

在本地“创建智能体”或“保存修改”主按钮下方加入网络操作按钮：

- 尚未上传的本地原创：`上传智能体`
- 已上传且当前用户是原作者：`同步到网络`
- 下载副本：按钮禁用，并显示“下载的智能体不能上传”说明

点击上传时：

1. 先校验名称、人设等现有必填字段。
2. 额外校验开场白去除首尾空白后非空。
3. 若是新建表单，先保存本地智能体，再进入标签补充步骤。
4. 用户选择预设标签或填写允许的自定义标签。
5. 提交新网络作品或更新已有网络作品。
6. 成功后把返回的网络归属元数据写回本地智能体，并提示“已提交 AI 审核”。

### 群聊

为 `GroupChat` 增加 `openingLine`，并在创建、编辑和网络上传表单中提供开场白输入框。上传按钮行为与智能体一致：

- 本地原创首次上传时创建网络群聊。
- 原作者同步时更新原网络群聊。
- 下载群聊副本禁止上传。
- 上传前开场白必须非空。

群聊开场白作为群聊配置和网络市场预览内容保存，不在本次改动中自动插入群消息，以免改变既有群聊消息和记忆语义。

### 保存时询问同步

编辑已绑定网络作品且当前用户是原作者时：

1. 用户点击“保存修改”。
2. 本地保存成功。
3. 弹窗询问“是否同步修改网络智能体/群聊？同步后将重新进行 AI 审核。”
4. 选择“仅保存本地”后关闭编辑页。
5. 选择“同步修改”后打开标签确认页，默认带入上一次标签；提交后更新原网络作品。

本地保存不依赖网络请求。同步失败时保留本地修改，停留或返回前明确提示网络同步失败，可由作者稍后再次点击“同步到网络”。

## 本地数据模型与数据库

### Agent 新增字段

```dart
final int? networkId;
final int? networkUploaderId;
final String networkSource; // none | owner | downloaded
final int? networkVersion;
```

### GroupChat 新增字段

```dart
final String? openingLine;
final int? networkId;
final int? networkUploaderId;
final String networkSource; // none | owner | downloaded
final int? networkVersion;
```

### SQLite 迁移

数据库版本从 32 升至 33，在 `agents` 和 `group_chats` 增加对应列。已有记录默认：

- `network_source = 'none'`
- 其他网络字段为 `NULL`

`_ensureGroupTablesExist()` 同步补齐群聊新增列，兼容历史迁移不完整的数据库。

这些字段加入现有 13 表同步中 `agents` 和 `group_chats` 的负载，不新增同步表。来源角色随多端同步，保证下载副本换设备后仍禁止上传。

### 上传资格规则

使用纯逻辑函数统一判断 UI 和业务层资格：

```dart
bool canUploadNetworkCopy({
  required String networkSource,
  required int? networkId,
}) => networkSource != 'downloaded';
```

- `none`：允许首次上传。
- `owner` 且有 `networkId`：允许更新原作品。
- `downloaded`：禁止新建和更新网络作品。

服务层不能只依赖按钮状态，提交前必须再次执行相同校验。

## 发现页下载与跳转

### 智能体

点击发现列表中的智能体卡片后：

1. 防止同一时间重复下载。
2. 调用 `POST /network/agents/:id/download`。
3. 反序列化并以新的本地 UUID 写入 `agents`。
4. 写入 `network_id`、`network_uploader_id`、`network_source='downloaded'` 和 `network_version`。
5. 设为当前智能体。
6. 进入该智能体聊天页。

### 群聊

点击发现列表中的群聊卡片后直接执行下载，不再要求先进入详情页才能下载：

1. 下载群聊配置与成员。
2. 为群聊和成员生成本地 ID，保持成员与群聊映射正确。
3. 群聊写入下载来源元数据和开场白。
4. 设为活动群聊。
5. 进入群聊页面。

下载或导入任一步失败时，不跳转；已经开始的数据库写入使用事务或显式回滚，避免留下半个群聊。

## 服务端 API 与权限

### 网络模型变更

`NetworkGroup` 新增：

```go
OpeningLine string `json:"opening_line"`
```

该字段与群人设、世界设定一样加密存储。`NetworkAgent.OpeningLine` 已存在。

### 上传请求来源声明

智能体和群聊的新建上传请求增加可选来源字段：

```json
{
  "source_network_id": null,
  "source_network_uploader_id": null,
  "source_kind": "none"
}
```

- 官方客户端上传本地原创时发送 `source_kind=none`。
- 下载副本发送或携带 `source_kind=downloaded` 时，服务端返回 403。
- 更新请求不接受客户端决定上传者，始终查询数据库并比较 JWT 用户 ID 与 `UploaderID`。

安全边界：该来源声明能够约束官方客户端和正常 API 流程，但无法证明用户是否把下载内容手工复制成一份没有来源信息的新文本。严格的抄袭识别需要独立的版权/相似度审核系统，不属于本次范围。

### 服务端必填校验

以下端点必须在服务端校验开场白去除首尾空白后非空：

- `POST /api/v1/network/agents`
- `PUT /api/v1/network/agents/:id`
- `POST /api/v1/network/groups`
- `PUT /api/v1/network/groups/:id`

失败返回 400 和明确中文错误，不依赖客户端校验。

### 作者权限

- 更新、下架和重新提交网络作品前，都必须满足 `record.UploaderID == JWT user_id`。
- 非作者统一返回 403。
- 客户端传入的 `uploader_id`、`network_source` 或网络作品 ID 不能覆盖数据库中的作者归属。
- 编辑已发布作品后状态重置为 `pending`，版本号加一，下载量保留。

## AI 自动审核状态机

上传或作者同步修改后，服务端异步触发 AI 审核：

```text
提交/修改
   |
   v
pending + AI running
   |--------------------------|
   v                          v
AI pass                    AI reject
approved                   rejected
公开展示                    仅作者可见原因

AI error/timeout/parse error -> 保持 pending，后台可重试
```

### 通过

同时写入：

- `AiReviewStatus = "pass"`
- `AiReviewReason = AI reason`
- `AiReviewedAt = now`
- `Status = "approved"`
- `RejectReason = ""`
- `ReviewedAt = now`
- `ReviewerID = 0`，表示自动审核

### 拒绝

同时写入：

- `AiReviewStatus = "reject"`
- `AiReviewReason = AI reason`
- `AiReviewedAt = now`
- `Status = "rejected"`
- `RejectReason = AI reason`
- `ReviewedAt = now`
- `ReviewerID = 0`

上传者可在“我上传的作品”查看拒绝状态和原因，修改后可再次提交审核。

### 审核异常

同时写入：

- `AiReviewStatus = "error"`
- `AiReviewReason = error message`
- `AiReviewedAt = now`
- `Status` 保持 `pending`

### 版本保护

触发异步审核时记录当前 `Version`。写回结果时使用同时匹配 ID、版本号和 `Status=pending` 的条件更新。若作者在审核期间再次修改，旧任务因版本不匹配而不能覆盖新提交。

### 配置行为

- `ai_review_enabled=true` 且 `ai_review_auto=true`：上传和编辑后自动审核并自动流转状态。
- AI 审核关闭或自动审核关闭：作品保持 `pending`，等待管理员人工审核。
- 管理员手动 AI 审核使用相同结果映射，也允许管理员随后人工批准、拒绝或下架。

## 用户可见状态

“我上传的作品”至少显示：

- 审核中
- 已上架
- 已拒绝及拒绝原因
- AI 审核异常/等待人工处理
- 已下架

作者同步修改已上架作品时，客户端明确提示作品会暂时从发现页移除，重新审核通过后恢复上架。

## 国际化

所有新增文本加入 `AppLocalizations` 的中文和英文条目，包括：

- 创建智能体、创建群聊
- 上传智能体、上传群聊、同步到网络
- 开场白是必须书写的
- 是否同步修改网络作品
- 仅保存本地、同步修改
- 已提交 AI 审核
- 下载的智能体/群聊不能上传
- 审核中、已上架、已拒绝、审核异常
- 修改已上架作品后将重新审核

## 测试策略

### Flutter 单元与 Widget 测试

1. `Agent` 和 `GroupChat` 网络来源字段的 `toMap/fromMap/copyWith` 往返一致。
2. v33 数据库迁移为旧记录填充 `network_source='none'`，并保留原数据。
3. `none` 和 `owner` 允许上传，`downloaded` 禁止上传。
4. 智能体和群聊上传时空白开场白均被拒绝。
5. 底部导航中央按钮不改变当前 Tab，菜单能选择两种创建类型。
6. 创建成功后进入正确聊天页。
7. 发现页智能体下载成功后写入 `downloaded` 来源并进入聊天页。
8. 群聊下载以事务落库，成功后进入群聊页，失败时不留下部分数据。
9. 原作者保存编辑后弹出同步询问；仅本地和同步两条分支行为正确。
10. 下载副本的上传按钮禁用，服务层直接调用也返回禁止结果。

### Go 测试

1. 智能体和群聊上传/编辑均拒绝空白开场白。
2. AI 通过自动把对应版本从 `pending` 更新为 `approved`。
3. AI 拒绝自动更新为 `rejected`，并把原因写入 `RejectReason`。
4. AI 异常保持 `pending`，同时记录 `AiReviewStatus=error`。
5. 旧版本审核结果不能覆盖新版本。
6. 非上传者不能编辑或下架网络作品。
7. 声明为下载来源的副本不能通过新建上传接口提交。
8. 人工审核仍可覆盖自动审核结果。

## 非目标

- 不做已下载作品的自动更新或版本合并。
- 不做内容相似度、版权归属或语义抄袭检测。
- 不允许下载者通过应用“另存为网络作品”。
- 不改变群聊消息、记忆和导演 AI 的现有语义。
- 不移除管理员人工审核、编辑、拒绝和下架能力。
- 不新增同步表，不改变“13 张用户数据表全量同步”的范围。

## 验收标准

1. 移动端底部导航中央存在可用的创建按钮，左右各两个主 Tab。
2. 创建菜单能进入智能体和群聊创建页，创建后直接进入聊天。
3. 智能体和群聊创建/编辑页均能补充标签并上传。
4. 没有开场白时客户端和服务端都拒绝上传。
5. 发现页点击作品后自动下载、导入并跳转聊天。
6. 下载副本在所有官方客户端路径中不能上传或更新网络作品。
7. 只有首次上传者能同步更新原网络作品。
8. 作者本地修改时可选择仅本地保存或同步修改网络作品。
9. AI 通过后自动上架，AI 拒绝后自动标记拒绝并展示原因。
10. 审核异常不误拒，旧版本审核结果不覆盖新版本。
11. Flutter 和 Go 的新增测试通过，完整分析、测试和构建命令通过。
