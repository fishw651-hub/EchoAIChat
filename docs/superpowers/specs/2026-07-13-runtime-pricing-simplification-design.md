# 运行设置收敛与峰谷计费设计

日期：2026-07-13  
状态：已确认，待实施

## 目标

移除用户侧的模型、思考模式与温度设置，让常规聊天使用一致且可预测的运行参数；同时取消订阅对 Pro 模型的限制，并在后台提供按时段调整价格的峰谷计费能力。

## 范围与非目标

- 普通私聊、普通群聊和记忆处理固定使用 `deepseek-v4-flash`、非思考模式、温度 `1.3`。
- OCR、提示词生成、模拟器是系统级特殊任务，不显示给用户配置；它们固定使用各自的高质量思考策略。
- 保留主题设置页，删除首次启动时的主题选择底部弹窗。
- 后台不再配置或执行 Pro Only、订阅计划模型限制、订阅计划允许模型和允许思考限制。
- 峰谷价格不改变订阅售价、充值售价或每日额度总额；它只改变一次调用从免费额度或订阅额度中消耗的金额。
- 不新增用户可选模型，也不改变模型的启用/停用与思考能力状态；这些仍是后台模型可用性控制。

## 运行参数

在客户端定义一个单一的运行策略来源，调用方不得再读取用户偏好：

| 场景 | 模型 | 思考 | 温度 |
| --- | --- | --- | --- |
| 普通私聊、普通群聊、记忆处理 | `deepseek-v4-flash` | 否 | `1.3` |
| OCR 分析 | 现有 OCR 专用模型 | 是 | 由思考协议决定，不发送温度 |
| AI 提示词生成 | `deepseek-v4-flash` | 是 | 由思考协议决定，不发送温度 |
| 模拟器导演与叙事 | `deepseek-v4-flash` | 是 | 由思考协议决定，不发送温度 |

客户端将删除设置页的“模型与模式”区块、仅含这些选项的智能体设置入口以及相关的模型切换提示。`SettingsState` 不再保存 `selected_model`、`thinking_mode`、`temperature`、订阅允许模型或允许思考状态；启动时会删除旧的 SharedPreferences 键。导入导出配置也不再读写这些字段。

`ApiService` 仍接受调用方传入的运行参数，以支持系统级特殊任务，但默认值改为 Flash、非思考和 `1.3`。普通聊天调用点只使用标准策略常量，不能由服务端订阅响应或旧本地配置改变模型。

## 主题弹窗

删除 `_AppShell` 启动后调用的初始主题检查和主题选择底部弹窗，以及 `theme_initial_choice_done` 标记。已有主题模式继续由设置页管理，历史标记可保留而不再读取。

## 订阅后台与模型权限

删除 `ModelPrice.ProOnly` 的后台编辑、接口字段和访问校验；同步模型时不再按模型名称推导 Pro Only。订阅计划编辑页、管理接口和公开计划响应均移除 `model_restrict`、`allowed_models` 和“允许思考”规则。

`SubscriptionPlanModel` 历史 JSON 数据不做破坏性删除，但不再被新代码读取或写入。旧订阅计划的 `ModelRestrict` 字段同样忽略。聊天服务只校验模型本身是否启用，以及在请求思考时该模型是否支持思考；订阅状态不再影响模型或思考能力。

## 峰谷计费

### 配置

使用现有 `SystemConfig` JSON 存储一项全局 `time_of_use_pricing` 配置：

```json
{
  "timezone": "Asia/Shanghai",
  "valley_start": "00:00",
  "valley_end": "08:00",
  "peak_multiplier": 1.0,
  "valley_multiplier": 1.0
}
```

后台增加“峰谷计费”配置区和受管理员权限保护的读取、更新接口。配置校验要求：时区固定为 `Asia/Shanghai`、时间为 `HH:mm`、开始与结束不得相同、倍率必须大于零且为有限数。时段可跨越午夜；谷时段为 `[valley_start, valley_end)`，其他时间为峰时段。缺少或损坏配置时使用上述默认值，确保升级后价格不发生变化。

### 计费流程

1. 服务器以 `Asia/Shanghai` 判断调用开始时属于峰或谷，并取得倍率。
2. 按现有模型基础价格、思考价格和活动折扣计算原始费用。
3. 将原始费用乘峰/谷倍率并按现有精度规则取整。
4. 预留额度时把时段、倍率和预留单价快照写入计费预留记录；结算必须使用同一倍率，避免长请求跨时段或管理员修改配置后产生预留与结算不一致。
5. 最终费用从免费额度或订阅额度中扣除。余额与支付金额不在本轮计费流程中扣除。
6. `UsageRecord` 记录计费时段和倍率，供后台审计和问题排查。

模型基础价格仍在“模型定价”中维护；峰谷倍率在独立配置区维护，避免为每个模型重复填写峰、谷价格。

## 错误处理与兼容性

- 未配置峰谷项、旧预留单和旧使用记录均按倍率 `1.0` 解释。
- 峰谷配置保存失败时返回明确的字段错误，保留已生效配置。
- 模型禁用或模型不支持思考仍返回现有可理解的错误；不再返回“当前订阅不支持模型”。
- 删除客户端旧偏好时不触及主题、语言、记忆轮数、登录态和其他设置。
- JSON 文件数据库允许模型字段扩展；旧记录缺少新增字段时由零值兼容逻辑补为默认值。

## 测试与验收

### Flutter

- 设置初始化清除旧模型、思考和温度偏好，但保留无关设置。
- 普通私聊、群聊和记忆调用均传入 Flash、非思考、温度 `1.3`。
- OCR、提示词生成和模拟器使用固定的特殊运行策略。
- 设置页面及首次启动流程不再渲染模型、思考、温度和主题底部弹窗。

### Go

- 峰谷判定覆盖普通时段、边界时刻和跨午夜时段。
- 成本倍率正确作用于基础价、思考价和活动折扣后的费用。
- 预留与结算使用同一倍率快照。
- 配置校验拒绝非法时间与非正倍率，缺失配置回退 `1.0`。
- 无订阅用户和任意订阅用户均可使用已启用的 Pro 命名模型；旧订阅模型规则不再限制请求。

验收命令：`flutter test`、`flutter analyze`（零 error）以及 `go test ./...`。
