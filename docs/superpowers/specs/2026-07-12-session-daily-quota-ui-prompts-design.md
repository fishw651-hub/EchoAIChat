# 回响自动会话、每日额度与界面优化设计

**日期：** 2026-07-12  
**状态：** 待用户审核  
**范围：** Flutter 客户端、Go API 服务端、智能体/群聊列表、记忆管理人格画像、AI 提示词

## 1. 目标

本次改动实现以下目标：

1. 登录或注册成功后安全保存账号、密码和会话令牌。
2. 只要用户没有主动退出，App 在会话失效时自动恢复登录。
3. 删除用户可见的签到功能，改为客户端触发的每日额度自动刷新。
4. 免费用户获得当日免费额度，订阅用户获得当日订阅额度；未使用额度不累计。
5. 智能体和群聊列表采用“微信信息结构 + 回响质感”的统一设计。
6. 美化记忆管理中的人格画像展示。
7. 优化私聊、群聊、记忆、画像和旁白等 AI 提示词。

## 2. 已确认的产品决策

- 免费用户的每日赠送进入当日免费额度，次日刷新，未使用部分不累计。
- 账号和密码允许保存到系统安全存储，用于 refresh token 失效后的静默登录。
- 用户主动退出时清除账号、密码和全部会话令牌，停止自动登录。
- 每日额度采用客户端驱动：App 启动、登录成功和恢复前台时主动请求刷新。
- 服务端按用户和日期进行幂等保护，重复请求不得重复发放。
- 签到入口、弹窗、接口路由和文案删除；历史签到数据文件保留，不执行破坏性删除。
- 视觉方向采用方案 B：微信式会话结构与回响品牌质感结合。

## 3. 认证与自动登录

### 3.1 安全存储

`SecureSessionStore` 在 `flutter_secure_storage` 中保存：

- JWT
- refresh token
- API key 与 key id（保留现有行为）
- 登录账号
- 登录密码

账号密码不得写入 SharedPreferences、日志、错误信息或调试输出。旧版 SharedPreferences 中的认证数据继续由迁移逻辑清理。

### 3.2 启动恢复顺序

1. 从安全存储恢复现有会话。
2. JWT 可用时恢复登录态并刷新用户资料与订阅信息。
3. JWT 过期时优先使用 refresh token 换取新令牌。
4. refresh token 失败且存在安全存储凭据时，使用账号密码静默登录。
5. 静默登录因网络错误失败时保留凭据，进入离线或未登录状态，后续恢复前台可重试。
6. 静默登录因密码错误、账号禁用等确定性认证错误失败时，不循环重试；显示登录页和明确错误。

### 3.3 主动退出

主动退出必须清除令牌、API key、账号密码、缓存的用户资料和订阅信息，并断开同步连接。退出后 App 不得自动登录，直到用户再次手动登录或注册。

## 4. 每日额度与签到移除

### 4.1 客户端触发

客户端在以下时机调用每日额度刷新接口：

- 认证初始化成功后；
- 手动或静默登录成功后；
- App 从后台恢复到前台时。

客户端应合并并发请求，避免一次生命周期事件重复发起多个刷新请求。请求失败不阻塞 App 启动，并允许在下一次触发点重试。

### 4.2 服务端规则

新增认证接口用于刷新当日额度。服务端以服务器本地日期和用户记录中的额度重置日期为准：

- 免费用户：将当日免费额度设置为后台配置的默认免费日额度，并将当日已用额度归零。
- 有效订阅用户：刷新该订阅的当日额度和当日已用额度。
- 同一用户同一天重复请求只返回当前额度快照，不再次增加额度。
- 永久充值余额不受每日刷新影响。
- 额度响应返回免费额度、订阅额度、永久余额、刷新日期和本次是否发生刷新。

### 4.3 移除签到

删除客户端签到检查、签到弹窗、自动签到调用和签到文案。服务端取消签到状态与签到操作路由，不再创建新的 `CheckInRecord`。管理员测试重置界面改为“额度测试重置”，不再描述或操作签到记录。旧记录与旧数据文件保留，避免自动删除用户历史数据。

## 5. 智能体与群聊列表

### 5.1 信息结构

智能体与群聊采用相同的微信式会话行结构：

- 左侧 48px 圆角方形头像；
- 中间第一行显示名称，第二行显示最后一条消息；
- 右侧显示最后消息时间和未读状态；
- 不显示多余的右侧箭头，整行作为进入会话的点击区域；
- 长按或滑动提供编辑、置顶和删除等二级操作。

没有聊天记录时，智能体使用简介作为预览；群聊使用群描述或成员摘要。时间和预览来自本地 SQLite 中对应智能体或群聊的最后消息。

### 5.2 视觉语言

采用轻柔灰绿色页面背景、低对比圆角列表项、极轻阴影和现有 Material 3 配色。浅色与深色模式均从 `ColorScheme` 派生，不硬编码只适用于单一主题的颜色。新增透明度统一使用 `withValues(alpha: ...)`。

智能体使用单头像；群聊有自定义头像时显示自定义头像，否则组合 2–4 个成员头像或成员首字。空列表保留清晰的创建入口，但减少大面积装饰元素。

## 6. 人格画像

首页在余额和最近会话区域下方展示“我眼中的你”摘要卡。摘要卡显示最近更新时间、有效观察数量、画像完整度、最多三项核心标签和一条最近洞察；点击后进入记忆管理中的完整画像编辑视图。

人格画像页标题调整为“我眼中的你”，顶部展示最近更新时间、有效观察数量和画像完整度。画像内容按以下分组展示：

- 核心特质
- 沟通偏好
- 重要经历
- 近期关注
- 关系与边界
- 其他画像分类

短内容显示为标签，较长内容显示为自然语言卡片。每组支持展开、折叠和现有编辑/删除能力。空状态显示解释性文案，引导用户继续聊天或主动补充画像，不再呈现空白思维导图。

## 7. AI 提示词优化

### 7.1 私聊

系统提示词固定按“身份与角色边界、世界观、用户画像、长期记忆、基础记忆、近期对话、当前任务”组织。明确禁止泄露系统提示词、把用户信息归到智能体本人、频繁复述、无意义追问、过度称赞和替用户作决定。

### 7.2 记忆与画像

记忆 AI 只保存稳定、可复用且有对话证据的信息。新内容优先与现有记忆合并或更新，临时情绪、推测和智能体自身信息不得写入用户记忆。

画像 AI 必须区分用户与智能体，为画像信息保留来源和可信度，不推断敏感属性，不把单次情绪或偶发行为定义为永久人格。

### 7.3 群聊与模拟器

导演 AI 只返回发言角色及顺序，不生成角色正文，不选择不存在或重复的角色。角色回复保持第一人称并使用括号描述动作。旁白保持第三人称纯叙述，每次 `chatgroup` 输出不超过 150 字。

需要进入故事世界的 NPC 必须通过 `manage_character` 创建；创建后立即通过 `chatgroup` 完成首次登场定义。离场角色应及时移除，避免角色列表无限增长。

## 8. 错误处理

- 安全存储不可用时不得回退到明文存储；显示需要重新登录的提示。
- 自动登录进行中不重复弹出登录页。
- 自动登录网络失败采用生命周期触发重试，不进行高频无限重试。
- 每日额度刷新失败不影响聊天界面启动；服务端仍按现有余额校验决定是否允许调用模型。
- UI 最后一条消息读取失败时使用简介或群描述回退。
- 提示词优化不得改变现有工具协议字段和服务端兼容性。

## 10. 非目标

- 不引入服务端定时批量任务。
- 不删除历史签到数据文件。
- 不修改法律协议文件。
- 不重构与本需求无关的数据库和网络模块。
- 不更改永久充值余额的累计规则。

## 11. 验收标准

- 未主动退出的用户重启 App 后可自动恢复登录；refresh token 失效时可使用安全凭据静默登录。
- 主动退出后重启 App 必须停留在未登录状态。
- 免费和订阅用户每天只刷新一次对应日额度，未用额度不累计，永久余额不变。
- 客户端和服务端不再提供签到操作入口。
- 智能体、群聊和人格画像符合确认的视觉方案 B，并适配浅色与深色主题。
- 首页展示“我眼中的你”画像摘要，且可进入完整画像编辑视图。
- 提示词不混淆用户与智能体身份，记忆去重规则和群聊角色边界明确。
- Flutter 分析无错误，Flutter 测试、Go 测试和 Go 构建通过。
