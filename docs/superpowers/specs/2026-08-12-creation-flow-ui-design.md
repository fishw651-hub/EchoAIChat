# 创建智能体与创建群聊界面优化设计

## 目标

优化 Flutter 客户端的 `AgentCreateScreen` 与 `GroupCreateScreen`，让首次创建更容易完成，同时保留现有高级能力和编辑能力。

本次采用“单页分组 + 渐进披露”方案：基础信息和首要决策始终可见，低频或高认知负担设置收纳到“更多设置”，不改变现有数据模型、保存接口和创建后的跳转行为。

## 已确认的产品决策

- 优先兼顾新手与高阶用户。
- 主流程保持单页滚动，不拆成多步向导。
- AI 帮写与导入能力作为首屏快捷入口。
- 群聊类型（普通群聊 / 模拟器模式）放在群聊页前部，并驱动后续内容动态切换。
- 创建页必须明确提供两条完成路径：`创建并开始聊天/进入群聊` 与 `创建并上传`；上传不是创建成功后的隐藏后续操作。
- 创建智能体成功后继续进入私聊；创建群聊成功后继续进入群聊。
- 编辑场景复用同一套分组结构，已保存数据预填充，编辑时不新增创建专属必填项。

## 页面结构

### 创建智能体

页面顺序：

1. 顶部栏
   - 返回。
   - 标题按创建/编辑状态变化。
   - 网络市场、草稿箱保留为右侧工具入口。
2. 身份基础
   - 头像预览与头像选择。
   - 名称（必填）。
   - 一句话介绍/描述。
   - 性别与称呼移入“更多设置”，避免首屏出现过多离散控件。
3. 首屏快捷入口
   - `AI 帮我创建`：继续使用现有 AI 提示词代写对话框，返回结果后更新名称、性别、描述、人设、开场白。
   - `从聊天导入`：继续使用现有截图 OCR 流程，保留识别中、无结果、配额不足和失败反馈。
4. 核心设定
   - 人设提示词（核心字段）。
   - 开场白（可选；上传网络代理时仍按现有规则校验必填）。
   - 人设字段保留占位符插入能力，导入聊天按钮在该分组标题行作为次级操作显示，避免与首屏快捷入口冲突。
5. 更多设置（默认折叠）
   - 性别与称呼。
   - 世界观。
   - 聊天背景与背景图片。
   - 真实信息与用户画像开关。
   - 主动关心开关及每日上限、最小间隔步进器。
   - 当前模型提示仍位于保存按钮附近，并可跳转账户页。
6. 固定的页面底部操作区（若当前页面结构允许）
   - 创建状态显示两个并列但有明确层级的完成动作：主按钮为`创建并开始聊天`，次级按钮为`创建并上传到网络市场`。
   - 编辑状态主按钮为`保存修改`；若当前智能体允许上传网络副本，则保留`保存并同步到网络`或进入现有网络同步确认流程。
   - `创建并上传到网络市场` 必须带云上传图标，不得藏在顶部工具菜单或创建成功后的二级页面。
   - 编辑状态下删除保持危险操作样式并与保存操作分离。

### 创建群聊

页面顺序：

1. 顶部栏
   - 返回、创建/编辑标题、网络市场和草稿箱工具入口保留。
2. 群聊身份基础
   - 群头像预览与选择。
   - 群聊名称（必填）。
   - 群聊简介。
3. 首屏快捷入口
   - `AI 帮我创建`：继续使用现有群聊提示词代写对话框。
   - `从截图导入`：保留截图 OCR、发言人审核、名称修订和导入结果提示。
4. 群聊类型
   - 使用顶部可见的分段选择：普通群聊 / 模拟器模式。
   - 选择结果立即更新说明文案和后续必填区域。
5. 普通群聊内容
   - 选择成员（必填）。
   - 截图导入结果在成员区附近显示为已识别发言人数和可复核状态。
   - 发言模式（自由发言 / 主持人模式）。
   - 主持人选择只在主持人模式且已有选中成员时显示。
6. 模拟器模式内容
   - 隐藏普通成员选择和主持人配置，避免出现无效字段。
   - 显示世界设定（核心字段）和开场情境。
   - 创建后继续使用现有模拟器初始化与旁白生成逻辑。
7. 更多设置（默认折叠）
   - 群聊整体设定/群人格提示词。
   - 公开开场白；仅本地创建时可选，选择`创建并上传到网络市场`时必填。
   - 记忆共用开关。
   - 其他不影响首次创建的外观或高级行为设置。
8. 页面底部主操作
   - 普通群聊：主按钮为`创建并进入群聊`，次级按钮为`创建并上传到网络市场`。
   - 模拟器：主按钮为`创建并进入模拟器`，次级按钮为`创建并上传到网络市场`；上传前沿用群聊上传页对模拟器/群聊字段的校验。
   - 编辑状态：主按钮为`保存修改`；已发布网络内容继续使用保存后的审核重置和网络同步提示，不绕过现有状态机。

### 创建并上传路径

- 智能体继续复用现有 `_saveAndUpload`：先执行本地表单保存和上传专属开场白校验，再携带 `localAgent` 进入 `NetworkUploadScreen(type: 'agent')`。
- 智能体的网络来源限制继续由 `canUploadNetworkCopy` 控制；下载来的受保护网络副本不可上传时，按钮保持禁用并显示原因，而不是点击后才失败。
- 群聊增加与智能体对称的创建页上传入口：先完成本地 `createGroup`，再携带刚创建的 `GroupChat` 进入 `NetworkUploadScreen(type: 'group', localGroup: group)`。成员、主持人、模拟器初始化和 OCR 导入结果必须在本地创建完成后再进入上传页。
- “创建并上传到网络市场”不直接提交审核：它完成本地创建并打开现有上传页，用户仍需复核公开内容、补充标签并点击发布，继续遵守 `pending -> approve/reject` 审核流程。
- 群聊上传继续使用现有 `openingLineRequired`/`hasRequiredOpeningLine` 规则：创建页点击“创建并上传到网络市场”时，如果公开开场白未填写，自动展开“更多设置”、将焦点/滚动定位到该字段并显示字段级错误；不能先创建后才让用户发现缺失。
- 上传页取消或上传失败时，不回滚已创建的本地智能体/群聊；返回创建页或继续进入本地聊天的行为遵循现有页面约定，并给出明确的本地已保存提示。
- 创建页的两个完成按钮都必须共享同一套 `_saving`/`_creating` 防重复提交状态；上传进行中显示进度，避免同时创建两份本地对象。

## 交互规则

### 渐进披露

- “更多设置”使用 `ExpansionTile` 或等价的语义折叠组件，默认关闭。
- 已有数据需要在编辑场景自动展开对应分组：例如真实信息已开启、主动关心已开启、模拟器群聊已有世界设定时，打开编辑页应保证用户能看到当前生效配置；是否自动展开可通过一个统一的 `hasAdvancedValues` 判断实现。
- 折叠/展开只改变内容可见性，不重置字段、不清空用户输入，也不改变保存语义。

### 群聊类型切换

- 普通群聊切换到模拟器时，不删除已选择成员；仅暂时隐藏普通群聊区域，用户切回后恢复选择。
- 模拟器切回普通群聊时，如果没有成员，保存时沿用现有 `selectMembersRequired` 校验并将错误反馈放在成员区域附近。
- 模拟器模式下，`speechMode`、主持人选择和普通成员必填校验不参与当前创建路径；保存时继续写入现有模型兼容字段。
- 类型切换应使用 150-300ms 的内容淡入/折叠过渡，并避免整体页面跳动过大。

### 校验与反馈

- 名称在提交时校验为空，错误显示在名称字段下方或通过现有 SnackBar 补充，不只依赖颜色。
- 人设、世界设定等复杂文本框提供稳定的可见标签和辅助说明，不使用 placeholder 作为唯一标签。
- 异步保存、AI 生成、OCR 导入时禁用对应触发器并显示进度，防止重复提交。
- OCR、配额不足、权限和网络错误沿用现有错误类型与文案，不新增静默失败路径。
- 创建成功后的导航和现有 provider 调用保持不变。

## 视觉与响应式约束

- 继续使用 `AppTheme` 的 Material 3 主题、Ocean 种子色和语义色，不引入页面级硬编码黑白颜色。
- 使用 4/8dp 间距节奏；分组间 20-24dp，字段间 12-16dp。
- 文本框和主要控件最小触达高度保持 44-48dp；颜色选择、图标按钮提供语义标签。
- 手机端单列滚动；桌面端可限制内容最大宽度并保持单列表单，避免在宽屏上把长文本字段拉得过宽。
- 底部主操作若采用固定区域，滚动内容必须预留安全区和底部内边距，不能遮挡最后一个字段。
- 深色模式沿用主题 surface/onSurface 对，检查输入框、折叠分组和禁用状态的对比度。

## 组件边界建议

保持现有页面文件和 provider 边界，不做无关重构。可在两个页面内部抽取少量私有构建方法：

- `_buildSectionHeader`：统一分组标题、说明和次级操作。
- `_buildQuickCreateActions`：统一 AI 帮写与导入入口的布局。
- `_buildAdvancedSection`：统一折叠行为和展开状态。
- 群聊页增加 `_buildGroupTypeSelector` 与 `_buildMemberSection`，将类型切换逻辑和成员区域的可见性集中管理。

不新增数据库字段，不修改 `Agent`、`GroupChat` 的持久化结构，不改变 `agentProvider`、`groupProvider` 的公开创建接口。

## 验收标准

### 功能

- 创建智能体的名称、核心人设、开场白、头像、世界观、真实信息、主动关心、背景和网络上传能力均可继续使用。
- 创建群聊的普通群聊、模拟器模式、成员选择、主持人模式、截图导入、群设定、公开开场白、记忆共用和网络上传能力均可继续使用。
- 两个创建页都清晰显示`创建并上传到网络市场`，并在进入上传页前完成上传专属校验。
- AI 帮写、OCR 导入、配额不足、保存失败和重复点击状态均有可见反馈。
- 创建/编辑/删除/上传后的导航行为与当前一致。

### 体验

- 首屏能在不展开高级设置的情况下完成最小可用创建。
- 群聊类型切换后不会展示与当前模式无关的字段。
- 低频设置默认折叠，但编辑已有配置时不会让用户误以为数据丢失。
- 375dp 宽度下无横向溢出，键盘弹出时主操作仍可通过滚动触达。
- 浅色和深色主题下，标签、辅助文字、禁用状态和选中状态均可辨识。

### 验证

- 新增或更新针对创建页的 widget 测试：首屏字段、折叠展开、群聊类型切换、必填校验、保存按钮 loading。
- 运行 `flutter analyze`，要求 0 errors。
- 运行相关 widget/unit tests，至少覆盖 `creation_provider_return_test.dart` 与新增创建页交互测试。
- 在小屏移动端、桌面宽屏、浅色和深色主题下进行手动检查。

## 非目标

- 不改创建数据模型、数据库迁移和 provider 业务规则。
- 不重新设计聊天页、网络市场、草稿箱和 AI 提示词对话框内部界面。
- 不在本次工作中增加模板市场、自动保存草稿或新的创建向导步骤。
