# 回响官网、管理后台与 DAU 趋势重构设计

## 目标

在不更换现有技术栈、不破坏管理后台业务功能的前提下，统一 `website/API/landing/` 与 `website/API/admin/` 的品牌视觉，提升手机、平板和桌面体验，并为管理后台新增可信的每日活跃用户统计与趋势折线图。

## 范围

### 包含

- 重构官网落地页的信息架构、视觉层级、交互与响应式布局。
- 移除官网浏览器端 Tailwind 编译，改用静态 CSS。
- 重构生产管理后台的导航、仪表盘、表格、表单、弹窗、登录页与响应式样式。
- 新增按天、按用户去重的 DAU 数据记录。
- 仪表盘新增今日 DAU、昨日对比、7/30/90 天趋势和原生 SVG 折线图。
- 补充相关 Go 测试和前端脚本回归检查。

### 不包含

- 不修改 Flutter 客户端。
- 不修改已弃用的 `website/API/frontend/admin/`。
- 不迁移到 React、Vue 或其他框架。
- 不引入外部图表库或新的运行时 CDN 依赖。
- 不改变现有计费、订阅、网络市场和同步业务规则。

## 方案比较

### 方案一：快速换皮

只修改颜色、圆角和阴影。改动小，但无法解决官网内容重复、后台信息密度失衡、移动端导航和表格体验差等结构问题。

### 方案二：渐进式结构重构（采用）

保留原生 HTML/CSS/JS 和既有 API，建立共享视觉 token，重排关键页面结构，抽离官网静态资源，并在不改变后台 DOM 业务契约的前提下升级外观与响应式行为。质量、风险和实施成本最平衡。

### 方案三：前端框架迁移

使用 React/Vue 重建官网和后台。长期组件化更强，但会显著扩大回归范围、部署复杂度和维护成本，不符合本轮目标。

## 品牌方向

视觉关键词为“静谧、回声、关系沉淀、可信赖”。主色延续客户端雾蓝，深色场景加入深海蓝，局部使用低饱和暖珊瑚作为“被回应”的情绪点缀。

- 主色：雾蓝与深海蓝，用于主要操作、选中状态和数据重点。
- 点缀：低饱和暖珊瑚，仅用于回声轨迹、关键数字和轻量强调。
- 表面：浅色采用冷白与雾灰，深色采用蓝黑与分层深蓝。
- 字体：系统中文字体优先，避免外部字体阻塞；标题使用更紧凑字距与 600–700 字重。
- 图标：使用一致的线性 SVG，不使用 Emoji 作为结构图标。
- 动效：150–280ms，优先 transform/opacity；遵守 `prefers-reduced-motion`。

## 官网设计

### 信息架构

1. 顶部导航：品牌、产品能力、记忆系统、群聊、隐私安全、下载。
2. 首屏：一句核心价值、简短说明、主下载按钮、查看能力次按钮、产品视觉。
3. 产品信任条：当前版本、Android、数据加密、持续更新。
4. 核心能力 Bento：长期记忆、人格画像、智能体、群聊、主动关心、多端同步。
5. 三层记忆叙事：短期、长期、基础人设的连续关系。
6. 群聊与智能体场景：用对话骨架表达真实使用体验。
7. 隐私与掌控：本地数据、可管理记忆、可控同步。
8. 下载 CTA 与页脚。

### 首屏

桌面使用左右分栏：左侧负责价值表达和下载，右侧用现有 `hero-main.jpg` 作为深海声波背景，叠加轻量产品界面卡片；手机改为单列，文案和 CTA 在前，视觉卡片在后。首屏不再使用整屏背景图压住文字，以提高可读性和品牌辨识度。

### 响应式

- `< 640px`：单列、全宽 CTA、抽屉导航、卡片纵向排列。
- `640–1023px`：双列能力卡、加宽内容边距、保持单列首屏。
- `>= 1024px`：双栏首屏、Bento 网格、最大内容宽度 1180px。
- `>= 1440px`：只增加留白，不无限拉长正文行宽。

### 性能与可访问性

- 删除 Tailwind 浏览器端编译和相关 CDN。
- CSS、JS 分别抽到 `css/landing.css` 与 `js/landing.js`。
- 保留结构化数据、SEO 元数据、动态版本和下载地址逻辑。
- 所有图标按钮提供 `aria-label`，键盘焦点清晰，触控区域至少 44px。
- 图片声明尺寸或宽高比，避免布局跳动。
- 无 JavaScript 时核心内容和下载链接仍可使用。

## 管理后台设计

### 页面骨架

- 桌面：248px 固定侧栏 + 顶部栏 + 内容画布。
- 平板：紧凑侧栏或抽屉，内容区域保持 16–24px 自适应边距。
- 手机：侧栏变为带遮罩抽屉；顶部栏保留当前页面标题和菜单按钮。
- 内容最大宽度不强制限制，数据表充分利用桌面空间。

### 视觉层级

- 侧栏使用深海蓝表面，当前项使用雾蓝状态层和左侧标识。
- 数据卡使用语义化图标、趋势值和辅助说明，不使用 Emoji。
- 表格使用更清晰的表头、斑马状态层、悬停/焦点反馈和粘性操作列。
- 表单统一标签、帮助文字、错误状态和 44px 最小高度。
- 弹窗统一遮罩、标题、内容、操作区，支持 ESC 与点击遮罩关闭。
- 登录页使用与官网一致的回声背景和品牌卡片。

### 仪表盘

顶部显示日期、服务状态和刷新操作。指标分为：

- 用户：总用户、今日新增、今日 DAU、较昨日变化。
- 业务：智能体数、订阅计划数、待处理订单。
- 成本：今日用量、累计用量。

趋势区提供 7/30/90 天切换。折线图为原生 SVG，包含横纵轴、渐变面积、数据点、悬浮/键盘提示、空状态和错误重试。图表下方提供文字摘要，便于无障碍读取。

## DAU 数据设计

### 统计口径

DAU 是在服务器本地时区内，当天至少成功通过一次用户鉴权并访问受保护 API 的去重普通用户数。管理员后台访问不计入产品 DAU，同一用户多设备、多请求只计一次。

### 数据模型

新增 `DailyActiveUser`：

- `ID`
- `UserID`
- `ActiveDate`，格式 `YYYY-MM-DD`
- `FirstActiveAt`

服务端进程内以 `日期:用户ID` 快速去重；首次命中时在互斥区内检查 JSON DB，避免并发重复插入。服务重启后仍通过持久化记录保持去重正确性。

### 采集位置

在 `AuthRequired` 完成 JWT 与用户状态校验后调用活跃追踪服务。追踪失败不阻断用户请求，但记录结构化错误日志。对同一用户当天后续请求只执行内存查找，不产生数据库写入。

### 仪表盘接口

扩展 `GET /api/v1/admin/dashboard?days=30`：

- `active_users_today`
- `active_users_yesterday`
- `active_change_percent`
- `dau_peak`
- `dau_average`
- `dau_trend: [{date, count}]`

`days` 仅允许 7、30、90，默认 30；无数据日期补零。统计以服务器配置时区为准。

## 错误处理

- 官网动态版本请求失败时保留静态版本与默认下载链接。
- 后台仪表盘失败时显示原因和重试按钮，不留下空白区域。
- DAU 写入失败只影响统计，不影响正常鉴权请求。
- 图表数据异常时过滤非法值并显示可恢复错误状态。

## 测试与验收

### 后端

- 同一用户同一天多次请求只产生一条活跃记录。
- 多用户、跨日期统计正确。
- 管理员不计入 DAU。
- 7/30/90 天补零和排序正确。
- 非法 `days` 参数回退或返回明确错误。
- `go test ./...` 通过。

### 前端

- 官网在 375px、768px、1024px、1440px 下无横向溢出。
- 后台导航、表格、弹窗在手机与桌面可操作。
- 键盘可以操作导航、筛选和折线图数据点。
- 深浅主题对比度、焦点、减少动画模式正确。
- 动态版本和下载链接继续工作。
- 浏览器控制台无错误，页面不依赖 Tailwind 运行时。

7. 运行 Go 测试、静态检查和多尺寸视觉验收。
