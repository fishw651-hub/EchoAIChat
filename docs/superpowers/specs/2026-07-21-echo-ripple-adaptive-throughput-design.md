# 回响波纹与自适应网络吞吐设计

日期：2026-07-21

## 目标

1. 首页“我眼中的你”卡片右上角的回响波纹不再漂移，以固定中心向外扩散。
2. 聊天请求保持低延迟，后台同步与批量传输自动利用剩余网络和服务器容量。
3. 网络空闲时允许后台任务尽量使用可用带宽；服务器出现压力、超时、429 或 5xx 时自动降载。
4. 不引入用户难以理解的手动网速档位，不改变现有聊天、同步和订阅业务规则。

## 非目标

- 不绕过操作系统和 TCP 拥塞控制。
- 不承诺达到运营商标称带宽；实际速度仍受客户端网络、TLS、磁盘、上游 AI 和服务器出口影响。
- 不让同步流量抢占聊天流式响应。
- 不重写现有同步协议或数据库格式。

## 回响波纹

`EchoOrbitRings` 保留独立 `RepaintBoundary`，固定使用同一个中心点。三个圆环使用错开的相位：

- 每个圆环从较小半径扩展到较大半径。
- 扩展过程中透明度逐渐降低。
- 圆心不做正弦漂移，半径不反向收缩。
- 动画循环衔接时依靠三组错峰相位维持连续感。
- 系统关闭动画、页面离开 `TickerMode` 或应用进入后台时停止动画，并显示稳定静态帧。

绘制只更新波纹区域，不触发卡片整体布局和重建。

## 网络优先级

网络请求分为两类：

### 高优先级

- AI 聊天与流式回复。
- 登录、鉴权刷新和必要的前台交互。

高优先级请求不等待后台同步额度。服务端接到聊天请求时直接进入现有鉴权、配额和上游调用链。

### 低优先级

- 多端同步预览与执行。
- WebSocket 通知触发的后台同步。
- 批量上传、下载与更新包传输。

低优先级任务服从自适应调度器。调度器不限制单连接字节速率，而是调节并发额度与重试间隔，让 TCP 在允许的连接上自然利用可用带宽。

## 客户端策略

1. `ApiService` 使用可复用的 HTTP Client，避免每次请求重复建立 TCP/TLS 连接。
2. 实时同步通知继续合并短时间内的重复事件，并根据最近一次同步结果动态选择下一次延迟：
   - 成功且耗时短：逐步缩短延迟。
   - 超时、连接失败、429 或服务器错误：指数退避并加入少量抖动。
   - 聊天正在进行：延后后台同步，聊天结束后再执行。
3. 同一设备只运行一个同步执行任务，后续通知合并为一次待处理同步，避免并发写 SQLite。
4. 请求成功后刷新智能体和群聊 Provider，网页端即时显示同步结果。

## 服务端策略

新增进程内自适应后台并发控制器，采用 AIMD：

- 初始额度为保守值。
- 连续成功且响应时间处于健康区间时，每个评估周期增加一个额度。
- 遇到超时、429、5xx 或高延迟时，额度快速减半。
- 额度始终位于配置的最小值和最大值之间。
- 聊天不消耗后台额度；同步、批量上传下载等后台任务才使用额度。
- 当后台额度已满时返回明确的 `429` 与 `Retry-After`，客户端据此退避，不无限排队占用内存和 goroutine。

上游 DeepSeek 调用改为复用共享 `http.Transport` 和 `http.Client`：

- 提高空闲连接池大小。
- 设置每主机空闲连接和总连接安全上限。
- 配置连接、TLS 握手、响应头和空闲连接超时。
- 流式请求保留长响应超时，不对正常 SSE 分块做额外缓冲。

## 配置

在服务端配置中增加可选的网络调优段，缺省值可直接工作：

- 后台最小并发。
- 后台最大并发。
- 健康延迟阈值。
- 过载延迟阈值。
- 上游每主机最大连接数。
- 上游空闲连接数。

所有字段都进行范围校验，非法值回退到安全默认值。生产环境可按 CPU、内存和出口带宽调大上限。

## 错误处理与可观测性

- 自适应控制只记录额度变化、过载和退避摘要，不记录 API Key、请求正文或聊天内容。
- 客户端同步失败保留现有数据，不清空本地状态。
- 服务端后台额度拒绝使用标准 429，避免伪装成服务器内部错误。
- 上游连接错误进入失败反馈，使并发额度快速降低。

## 测试与验收

### Flutter

- Painter 在多个动画时刻使用同一圆心。
- 每个波纹在自身周期内半径单调增大，透明度单调降低。
- 关闭动画时控制器停止。
- 同步通知合并且同一时间只执行一个同步。

### Go

- AIMD 成功路径逐步增大且不超过最大值。
- 失败或过载路径减半且不低于最小值。
- 后台额度耗尽返回 429 和 `Retry-After`。
- 共享 HTTP Transport 的连接池参数来自配置并经过边界校验。
- 聊天路由不受后台额度阻塞。

### 验证命令

- `flutter test` 的相关定向测试。
- `flutter analyze --no-pub`，要求没有新增 error。
- `go test ./...`；若 Windows 临时 SQLite 文件锁导致清理失败，需单独确认本次新增包和定向测试通过。
- `go build -o aichat-api.exe .`。

## 部署

Flutter 客户端需重新构建。Go 后端需重新编译并重启。先使用默认参数上线，观察聊天延迟、同步 429 比例和服务端资源后，再调整最大后台并发与上游连接上限。
